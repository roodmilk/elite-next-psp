## Before changing anything

1. `git pull --rebase --autostash` and `git submodule update --init --recursive`
2. Baseline build + smoke: `./build.ps1` / `./smoke-test.ps1` on Windows, or `./build.sh` / `./smoke-test.sh` on Linux
3. Report pass/fail and version. Do not claim features that are only designed.

## Hard constraints

- Preserve PSP 480×272 readability, save migration, mission idempotency, custom MP3 streaming and suspend/resume behaviour.
- Quator is only an ordinary generated system; the full-galaxy route planner must work generically for every tracked destination.
- Be honest about proposed design versus functionality that is actually playable.

## After each coherent change

1. Add meaningful regressions
2. Rebuild and run the full smoke suite (zero failures)
3. Update `VERSION`, `build.ps1` (and `build.sh` if present), `CHANGELOG.md`, `CLAUDE-HANDOFF.md` together
4. Copy tested `EBOOT.PBP` to `dist/ELITE-NEXT-PSP/EBOOT.PBP`
5. Commit, push, open/update a PR; tag `v<version>` only for a public downloadable build
